# Rule 1. We don't write code until we understand the problem.

# Steps to design a system
1. What are the responsibilities?
2. Turn responsibilities into modules
3. Design the contracts

# Function Thinking
1. What is this function responsible for?
2. What information does it need?
3. What should it return?
4. Who should call it?

# For every worker (Function), define:

Job description (purpose)
Inputs (what they receive)
Output (what they produce)
Who they report to (caller)
Who they depend on (other functions)

# Engineering Principles
1. Design responsibilities before designing functions.
2. One responsibility. One owner.
3. Who needs this return value?
4. Data should flow downward
5. Choose the right data structure first.
6. High-level modules should coordinate. Low-level modules should specialize.
7. Contracts before code.
8. A function should have one clear responsibility and one clear return value.
9. Good engineers reuse architectures, not just code.
10. Am I describing something that exists, or am I recording something that happened?

Programming is writing instructions that make the computer work. 
Software engineering is organizing those instructions so humans 
can understand, extend, test, and maintain them.
